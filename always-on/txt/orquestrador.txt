# Como montar o orquestrador e os agentes  
O orquestrador é uma sessão do Claude Code (https://claude.com/product/claude-code) que fica sempre aberta no app. Você pede a tarefa a ele, e ele abre um agente por tarefa, na pasta do projeto, com teto de RAM próprio. O agente é outra sessão do Claude Code, que faz o trabalho. O orquestrador distribui as tarefas, acompanha os agentes e relata o resultado. 
O instalador (txt/instalador.txt) faz esta página com um comando. Ela fica para quem monta à mão ou quer entender cada peça. 

- Você pede, pelo celular 
- Orquestrador confere, agentes vivos e o repo 
- Abre o agente, na pasta, com teto 
- Agente trabalha, testa e commita 
- Avisa que acabou, no app ou no Telegram 
- Encerra o agente, a memória volta  

## Por que um orquestrador 

- O Remote Control (https://code.claude.com/docs/en/remote-control) liga uma sessão da máquina ao app do Claude. Sem orquestrador, cada projeto novo pede um serviço do Remote Control próprio, criado à mão. Com o orquestrador, projeto novo é uma linha no `projects.json`. 
- Cada agente nasce dentro do slice dos agentes, o grupo do systemd (https://systemd.io/) com um teto de memória para todos eles somados, com o teto do projeto, e um projeto pesado não derruba os outros. 
- O agente abre na pasta do projeto e carrega o `CLAUDE.md`, a memória e os hooks dele.  

## Duas formas de pôr uma sessão no app 

| Forma | Como | Quem usa |
| --- | --- | --- | 
| Modo servidor | `claude remote-control` espera, e abre uma sessão nova cada vez que você pede pelo app | O recover, a sessão de socorro, e a entrada de reserva do orquestrador | 
| Sessão de terminal ligada ao app | `claude --remote-control <nome>` num tmux (https://github.com/tmux/tmux). A sessão aparece pronta no app, com a pasta, o teto e a tarefa com que nasceu | O orquestrador e os agentes |  
Se o app não conseguir abrir uma sessão, use a segunda forma: entre pelo SSH, abra um tmux e rode `claude --remote-control <nome>` na pasta. 

## O nome e a pasta 
Escolha um nome para o orquestrador. Ele é o nome da sessão no app e o endereço que os agentes usam no `SendMessage`. Nesta página, o nome aparece como `<orquestrador>`, e o slice dos agentes como `<slice>`. 
O `projects.json` lista cada projeto com a pasta e o teto de RAM do agente: 

bash, na máquina
```
mkdir -p ~/<orquestrador> && cat > ~/<orquestrador>/projects.json <<'EOF'
{
  "site": { "path": "~/repos/site", "memory": "1536M" },
  "api":  { "path": "~/repos/api",  "memory": "3G" }
}
EOF
```

O nome do orquestrador e o slice ficam num arquivo que o comando `agent`, o script do serviço e os timers leem, também numa sessão aberta pelo SSH: 

bash, na máquina
```
mkdir -p ~/.config/always-on && printf 'AGENT_ORCHESTRATOR=%s\nAGENT_SLICE=%s.slice\n' <orquestrador> <slice> > ~/.config/always-on/env
```

O `CLAUDE.md` da pasta diz ao orquestrador o que ele faz e o que ele não faz: 

bash, na máquina
```
cat > ~/<orquestrador>/CLAUDE.md <<'EOF'
# Orquestrador

Você é o orquestrador dos agentes desta máquina. Eu converso com você pelo app, e você entrega cada tarefa a um agente aberto na pasta do projeto. O agente faz o trabalho. Você distribui, acompanha e relata, e não mexe em código, dado nem configuração de projeto.

## Os projetos

`projects.json`, nesta pasta, lista cada projeto com a pasta e o teto de RAM. Projeto novo entra lá antes do primeiro agente.

## O comando `agent`

| Comando | O que faz |
| :--- | :--- |
| `agent start <projeto> [--worktree BRANCH] [--name NOME] "<tarefa>"` | Abre o agente na pasta do projeto, em bypass, com o teto do projeto e já com a tarefa. Com `--worktree`, ele trabalha numa branch própria, num worktree do git. Devolve o nome e o link no app |
| `agent list` | Agentes vivos, com projeto, RAM usada e teto |
| `agent result <nome>` | A última resposta do agente, lida do transcript |
| `agent stop <nome>` | Encerra o agente, devolve a RAM e conclui as tarefas com `[<nome>]` no assunto. Com `--keep-tasks`, encerra sem concluir |

Arquivar a sessão no app não encerra o processo. Todo agente termina com `agent stop`.

## Pedido vira tarefa

Os pedidos em aberto moram na lista nativa de tarefas do Claude Code, a lista `<orquestrador>`, em `~/.claude/tasks/<orquestrador>/`. Ela fica no disco e volta depois de cada compactação.

- Pedido novo meu vira `TaskCreate` antes de qualquer outra ação, uma tarefa por pedido. O assunto começa com o dono entre colchetes: o nome do agente, ou `eu` quando o item espera uma decisão minha. Exemplo: `[site] trocar o rodapé`.
- Ao disparar o agente, marque `in_progress`.
- Conclua só depois de me relatar o resultado. O `agent stop <nome>` conclui as tarefas `[<nome>]`, então pare o agente depois do relato.

## Antes de disparar

1. `agent list` e `ListAgents`: quem está vivo, em qual projeto, ocupado ou ocioso.
2. No repo do projeto, `git status` e a branch atual.
3. Já existe agente no mesmo assunto: mande a tarefa para ele com `SendMessage`. Senão, abra um novo. Com outro agente vivo no mesmo repo, abra o novo com `--worktree <branch>`, para os dois não mexerem na mesma árvore.

## Enquanto o agente trabalha

Peça `notify_when_idle` ao disparar e a cada continuação. Quando o aviso chegar, leia com `agent result` e me relate em uma ou duas linhas: o que entrou, o que rodou, o que falta. Agente que entregou sai com `agent stop`. Quando o próprio agente avisar que terminou, rode `agent stop` e me conte em uma linha.

## RAM

Os agentes somados dividem o teto do slice. Antes de abrir um agente pesado, confira o `agent list`. Se a soma dos tetos vivos passar do teto do slice, me avise e espere a vez.
```

## O comando agent 
Este comando abre, lista e encerra os agentes. Cada agente roda num tmux próprio, um terminal que segue rodando sem o SSH, dentro de um scope do systemd, um grupo de processos criado na hora, no slice dos agentes e com o teto do projeto. O comando usa `sudo -n systemd-run`, então o usuário precisa do sudo sem senha configurado em Como fazer a config inicial da VPS (txt/preparar.txt). Ver o script do comando agent (302 linhas) 

bash, na máquina
```
cat > ~/.local/bin/agent <<'EOF'
#!/usr/bin/env python3
"""Abre, lista e encerra os agentes do orquestrador, cada um com teto de RAM próprio.

  agent start <projeto> [--worktree BRANCH] [--role PAPEL] [--name NOME] [--resume SESSAO] [--chrome] "<tarefa>"
  agent list
  agent result <nome>
  agent stop [--keep-tasks] <nome>

A pasta e o teto de cada projeto vêm do projects.json do orquestrador. AGENT_ORCHESTRATOR é o nome
do orquestrador no app, e AGENT_SLICE o slice dos agentes. Os dois vêm do ambiente ou, fora dele,
de ~/.config/always-on/env, que vale também para o SSH.
"""

import json
import os
import pwd
import re
import subprocess
import sys
import time
import uuid
from pathlib import Path

HOME = Path.home()
USER = pwd.getpwuid(os.getuid()).pw_name

def setting(key, default):
    if os.environ.get(key):
        return os.environ[key]
    try:
        for line in (HOME / ".config" / "always-on" / "env").read_text().splitlines():
            k, _, v = line.partition("=")
            if k.strip() == key and v.strip():
                return v.strip()
    except OSError:
        pass
    return default

ORCHESTRATOR = setting("AGENT_ORCHESTRATOR", "orquestrador")
PROJECTS = Path(os.environ.get("AGENT_PROJECTS", HOME / ORCHESTRATOR / "projects.json"))
SLICE = setting("AGENT_SLICE", "agents.slice")
STATE = HOME / ".local" / "state" / "agents"
RUNTIME_DIR = f"/run/user/{os.getuid()}"
# A lista de pedidos do orquestrador, o CLAUDE_CODE_TASK_LIST_ID do serviço dele. O agente usa a lista
# da própria sessão, e o agent stop conclui aqui as tarefas com [<nome>] no assunto.
TASKS = HOME / ".claude" / "tasks" / re.sub(r"[^a-zA-Z0-9_-]", "-", setting("CLAUDE_CODE_TASK_LIST_ID", ORCHESTRATOR))
# O orquestrador encerra o agente quando recebe o aviso. Numa conversa direta com a pessoa, o aviso
# antes da hora derrubaria a sessão no meio da conversa.
DONE_PROMPT = ("Você é o agente {name}, aberto pelo {orch}. Quando concluir o trabalho e não houver mais "
               "nada pendente, mande SendMessage para {orch} com \"{name} terminou, pode encerrar\" e uma "
               "linha do que entregou. Se alguém estiver conversando direto com você, avise só quando a "
               "pessoa disser que acabou.")

def die(msg):
    print(f"agent: {msg}", file=sys.stderr)
    sys.exit(1)

def tmux(name, *args):
    return subprocess.run(["tmux", "-L", name, *args], capture_output=True, text=True)

def pane(name):
    return tmux(name, "capture-pane", "-p", "-S", "-200", "-t", name).stdout

def agent_pid(name):
    out = subprocess.run(["pgrep", "-f", f"^claude .*--remote-control {name}( |$)"],
                         capture_output=True, text=True).stdout.split()
    return int(out[0]) if out else None

def cgroup(pid):
    try:
        return Path(f"/proc/{pid}/cgroup").read_text().split("::", 1)[1].strip()
    except (OSError, IndexError):
        return None

def mib(path):
    try:
        v = Path(f"/sys/fs/cgroup{path}").read_text().strip()
        return "max" if v == "max" else f"{int(v) // 2**20}M"
    except OSError:
        return "?"

def trust(path):
    # A pasta-mãe confiável não cobre um repo com .claude próprio, e a tela "trust this folder"
    # travaria o agente na subida.
    cfg = HOME / ".claude.json"
    data = json.loads(cfg.read_text())
    entry = data.setdefault("projects", {}).setdefault(str(path), {})
    if entry.get("hasTrustDialogAccepted"):
        return
    entry["hasTrustDialogAccepted"] = True
    tmp = cfg.with_suffix(".json.agent")
    tmp.write_text(json.dumps(data, indent=2))
    os.replace(tmp, cfg)

def start(argv):
    opts, rest = {}, []
    it = iter(argv)
    for a in it:
        if a in ("--worktree", "--role", "--name", "--resume"):
            opts[a[2:]] = next(it, None) or die(f"{a} precisa de um valor")
        elif a == "--chrome":
            opts["chrome"] = True
        else:
            rest.append(a)
    if len(rest) != 2:
        die('uso: agent start <projeto> [--worktree BRANCH] [--role PAPEL] [--name NOME] [--resume SESSAO] '
            '[--chrome] "<tarefa>"')
    project, task = rest
    try:
        cfg = json.loads(PROJECTS.read_text()).get(project) or die(f"projeto {project} fora de {PROJECTS}")
    except FileNotFoundError:
        die(f"{PROJECTS} não existe")
    path = Path(os.path.expanduser(cfg["path"]))
    if not path.is_dir():
        die(f"{path} não existe")
    trust(path)
    role = opts.get("role")
    if role and not any((d / ".claude" / "agents" / f"{role}.md").is_file() for d in (path, HOME)):
        die(f"papel {role} não existe; crie {path}/.claude/agents/{role}.md")
    name = opts.get("name") or f"{project}-{role or uuid.uuid4().hex[:4]}"
    if agent_pid(name) or tmux(name, "has-session").returncode == 0:
        die(f"{name} já está rodando")

    STATE.mkdir(parents=True, exist_ok=True)
    spec = {"name": name, "project": project, "path": str(path), "task": task, "memory": cfg["memory"],
            "session": opts.get("resume") or str(uuid.uuid4()), "resume": bool(opts.get("resume")),
            "worktree": opts.get("worktree"), "role": role, "chrome": bool(opts.get("chrome")),
            "orchestrator": ORCHESTRATOR,
            "started": time.strftime("%Y-%m-%dT%H:%M:%S")}
    (STATE / f"{name}.json").write_text(json.dumps(spec, indent=2))

    # Um servidor tmux por agente: com um servidor só, o segundo agente nasceria no scope do primeiro.
    # O tmux nasce sem XDG_RUNTIME_DIR: com ele, o tmux muda o painel para fora do scope.
    shell = os.environ.get("SHELL", "/bin/bash")
    inner = f"exec {os.path.realpath(sys.argv[0])} _run {name}"
    # O setpriv devolve o usuário com todos os grupos dele, como o docker. O --uid do systemd-run
    # deixaria só o grupo principal, mais o root.
    subprocess.run(["sudo", "-n", "systemd-run", "--scope", "-q", f"--slice={SLICE}",
                    "-p", f"MemoryMax={cfg['memory']}", f"--working-directory={path}",
                    "setpriv", f"--reuid={os.getuid()}", f"--regid={os.getgid()}", "--init-groups",
                    "env", f"HOME={HOME}", f"USER={USER}", f"LOGNAME={USER}",
                    "tmux", "-L", name, "new-session", "-d", "-s", name, f"{shell} -lic '{inner}'"],
                   check=True)

    for _ in range(60):
        if tmux(name, "has-session").returncode != 0:
            (STATE / f"{name}.json").unlink(missing_ok=True)
            die(f"{name} saiu na subida; veja o erro com: agent _run {name}")
        screen = pane(name)
        if "trust this folder" in screen:
            stop([name])
            die(f"{path} não está marcada como confiável; abra o claude nela uma vez e aceite")
        if "bypass permissions on" in screen:
            break
        time.sleep(1)
    else:
        die(f"{name} não subiu em 60 s; veja com: tmux -L {name} attach")

    link = "?"
    for _ in range(20):
        link = next((w for w in pane(name).split() if w.startswith("https://claude.ai/code/session_")), "?")
        if link != "?":
            break
        time.sleep(1)
    pid = agent_pid(name)
    print(f"{name}  pid {pid}  {cgroup(pid)}  teto {cfg['memory']}\n{link}")

def run(name):
    spec = json.loads((STATE / f"{name}.json").read_text())
    cmd = ["claude", "--permission-mode", "bypassPermissions", "--remote-control", name, "--name", name,
           "--resume" if spec["resume"] else "--session-id", spec["session"],
           "--append-system-prompt", DONE_PROMPT.format(name=name, orch=spec["orchestrator"])]
    # O --worktree abre o agente num worktree do git, numa branch própria: dois agentes no mesmo repo
    # não mexem na mesma árvore.
    if spec.get("worktree"):
        cmd += ["--worktree", spec["worktree"]]
    if spec.get("role"):
        cmd += ["--agent", spec["role"]]
    if spec.get("chrome"):
        cmd += ["--chrome"]
    cmd.append(spec["task"])
    # O sudo limpa o ambiente, então o nome do orquestrador vem do spec gravado no start.
    # Sem XDG_RUNTIME_DIR, o socket de mensagens cai em /tmp e o orquestrador não enxerga o agente.
    os.environ["XDG_RUNTIME_DIR"] = RUNTIME_DIR
    # As ferramentas de tarefa somem nos modelos novos sem a variável. A lista de pedidos é só do
    # orquestrador: o agente fica com a da própria sessão.
    os.environ["CLAUDE_CODE_ENABLE_TODO_TOOLS"] = "1"
    os.environ.pop("CLAUDE_CODE_TASK_LIST_ID", None)
    os.execvp("claude", cmd)

def list_():
    rows = []
    for f in sorted(STATE.glob("*.json")):
        spec = json.loads(f.read_text())
        pid = agent_pid(spec["name"])
        if not pid:
            f.unlink()
            continue
        cg = cgroup(pid) or ""
        branch = subprocess.run(["git", "-C", spec["path"], "branch", "--show-current"],
                                capture_output=True, text=True).stdout.strip() or "-"
        rows.append((spec["name"], spec["project"], spec.get("worktree") or branch,
                     f"{mib(cg + '/memory.current')}/{mib(cg + '/memory.max')}", spec["started"]))
    if not rows:
        print("nenhum agente rodando")
        return
    rows.insert(0, ("NOME", "PROJETO", "BRANCH", "MEMÓRIA", "INÍCIO"))
    widths = [max(len(r[i]) for r in rows) for i in range(5)]
    for r in rows:
        print("  ".join(c.ljust(w) for c, w in zip(r, widths)).rstrip())

def result(argv):
    f = STATE / f"{argv[0]}.json" if len(argv) == 1 else die("uso: agent result <nome>")
    if not f.exists():
        die(f"{argv[0]} não está rodando")
    spec = json.loads(f.read_text())
    found = list((HOME / ".claude" / "projects").glob(f"*/{spec['session']}.jsonl"))
    if not found:
        die(f"{argv[0]} ainda não tem transcript")
    last = None
    for line in found[0].read_text().splitlines():
        msg = json.loads(line).get("message") or {}
        if msg.get("role") == "assistant" and isinstance(msg.get("content"), list):
            text = "".join(b.get("text", "") for b in msg["content"] if b.get("type") == "text")
            last = text if text.strip() else last
    print(last or f"{argv[0]} ainda não respondeu")

def complete_tasks(name):
    """Conclui as tarefas abertas da lista do orquestrador com [<nome>] no assunto."""
    tag, done = f"[{name.lower()}]", []
    for f in sorted(TASKS.glob("*.json")):
        try:
            t = json.loads(f.read_text())
        except (OSError, ValueError):
            continue
        if t.get("status") == "completed" or tag not in str(t.get("subject", "")).lower():
            continue
        t["status"] = "completed"
        note = f"Concluída pelo agent stop {name} em {time.strftime('%Y-%m-%dT%H:%M:%S')}."
        t["description"] = f"{t['description']}\n\n{note}" if t.get("description") else note
        tmp = f.with_name(f".{f.name}.agent")
        tmp.write_text(json.dumps(t, indent=2, ensure_ascii=False))
        os.replace(tmp, f)
        done.append(f"#{t.get('id')}")
    return done

def stop(argv):
    keep = "--keep-tasks" in argv
    argv = [a for a in argv if a != "--keep-tasks"]
    name = argv[0] if len(argv) == 1 else die("uso: agent stop [--keep-tasks] <nome>")
    pid = agent_pid(name)
    tmux(name, "kill-server")
    for _ in range(30):
        if not pid or not Path(f"/proc/{pid}").exists():
            break
        time.sleep(1)
    else:
        die(f"{name} (pid {pid}) segue vivo depois de 30 s")
    spec_file = STATE / f"{name}.json"
    if spec_file.exists():
        spec = json.loads(spec_file.read_text())
        with open(STATE / "stopped.jsonl", "a") as f:
            f.write(json.dumps({"name": name, "project": spec["project"], "session": spec["session"],
                                "path": spec["path"], "stopped": time.strftime("%Y-%m-%dT%H:%M:%S")}) + "\n")
        spec_file.unlink()
    done = [] if keep else complete_tasks(name)
    print(f"{name} encerrado" + (f"; tarefas concluídas: {' '.join(done)}" if done else ""))

def main():
    if len(sys.argv) < 2:
        die(__doc__.split("\n\n")[1])
    cmd, argv = sys.argv[1], sys.argv[2:]
    if cmd == "start":
        start(argv)
    elif cmd == "list":
        list_()
    elif cmd == "result":
        result(argv)
    elif cmd == "stop":
        stop(argv)
    elif cmd == "_run":
        run(argv[0])
    else:
        die(f"comando desconhecido: {cmd}")

if __name__ == "__main__":
    main()
EOF
chmod 755 ~/.local/bin/agent
```

- Um servidor tmux por agente, com `tmux -L <nome>`. Com um servidor compartilhado, o segundo agente nasce dentro do scope do primeiro e herda o teto dele. 
- O `XDG_RUNTIME_DIR` vai só para o `claude`, nunca para o tmux. Sem ele, o socket de mensagens cai em `/tmp` e o orquestrador não acha o agente. Com ele no tmux, o painel sai do scope e do teto. 
- O comando marca a pasta do projeto como confiável antes de abrir. Sem isso, o agente trava na tela "trust this folder". 
- O `setpriv --init-groups` abre o agente com todos os grupos do usuário. Com o `--uid` do `systemd-run`, ele nasceria só com o grupo principal mais o `root`, e o `docker` falharia por falta de permissão.  

## O serviço 
O script sempre retoma a última conversa, e o laço sobe o orquestrador de novo se ele sair: 

bash, na máquina
```
cat > ~/.local/bin/orchestrator-rc <<'EOF'
#!/bin/sh
# O orquestrador sobe pelo terminal, com --remote-control, e volta sempre na última conversa.
# O --continue sai na hora quando não há conversa, e aí ele abre uma nova.
# O nome do orquestrador e o slice dos agentes vêm de ~/.config/always-on/env, que o comando agent também lê.
. "$HOME/.config/always-on/env" || exit 1
export AGENT_ORCHESTRATOR AGENT_SLICE
cd "$HOME/$AGENT_ORCHESTRATOR" || exit 1
# Sem XDG_RUNTIME_DIR, o socket de mensagens cai em /tmp e os agentes não acham o orquestrador.
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
export PATH="$HOME/.local/bin:$PATH"
set -- --permission-mode bypassPermissions --remote-control "$AGENT_ORCHESTRATOR" --name "$AGENT_ORCHESTRATOR"
# Com o bot do Telegram configurado, o orquestrador abre o canal dele. O canal roda em Bun.
# O plugin liga só nesta sessão, pelo --settings: sessão nova com ele ligado derruba o leitor do bot
# que estiver rodando, e a entrada de reserva (orchestrator-spawn) abre sessões nesta mesma pasta.
if [ -f "$HOME/.claude/channels/telegram/.env" ]; then
    export PATH="$HOME/.bun/bin:$PATH"
    set -- "$@" --settings '{"enabledPlugins":{"telegram@claude-plugins-official":true}}' \
        --channels plugin:telegram@claude-plugins-official
fi
while true; do
    t=$(date +%s)
    claude --continue "$@"
    [ $(($(date +%s) - t)) -lt 5 ] && claude "$@"
    sleep 10
done
EOF
chmod 755 ~/.local/bin/orchestrator-rc
```

Na pasta, rode uma vez à mão `claude --dangerously-skip-permissions --remote-control <orquestrador>`. Escolha o tema, aceite a confiança na pasta, o Remote Control e o aviso do bypass, o modo em que a sessão roda comandos sem pedir permissão, e saia com `/exit`. Depois grave o serviço, com `voce` trocado pelo seu usuário e `<uid>` pela saída de `id -u`. O orquestrador não roda comando pesado, e 1 GiB de teto basta para ele. 

bash, na máquina
```
sudo tee /etc/systemd/system/<orquestrador>.service > /dev/null <<'EOF'
[Unit]
Description=Orquestrador dos agentes do Claude Code
After=network-online.target user-runtime-dir@<uid>.service
Wants=network-online.target user-runtime-dir@<uid>.service

[Service]
# A lista de pedidos: sem a primeira variável, os modelos novos não têm as ferramentas de tarefa.
Environment=CLAUDE_CODE_ENABLE_TODO_TOOLS=1
Environment=CLAUDE_CODE_TASK_LIST_ID=<orquestrador>
Type=forking
User=voce
Slice=<slice>.slice
MemoryHigh=768M
MemoryMax=1G
OOMPolicy=continue
ExecStart=/usr/bin/tmux -L <orquestrador> new-session -d -s <orquestrador> "bash -lic orchestrator-rc"
ExecStop=/usr/bin/tmux -L <orquestrador> kill-server
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF
sudo loginctl enable-linger $USER
sudo systemctl daemon-reload && sudo systemctl enable --now <orquestrador>
```

## A entrada de reserva 
Quando a sessão do orquestrador cai, você abre outra pelo app, sem SSH e sem passar pelo recover. Um segundo serviço roda o Remote Control no modo servidor na pasta do orquestrador. No app, ele aparece como mais um lugar para abrir sessão nova, ao lado do recover, e a sessão aberta ali lê o `CLAUDE.md` da pasta e já nasce orquestrador. 

- Sobe sem sessão pré-criada, com `--no-create-session-in-dir`. Parado, o serviço ocupa uns 70 MB. Uma sessão ociosa ali gastaria de 200 a 500 MB do slice. 
- Plugin que só pode rodar numa sessão, como o do Telegram, liga pela linha de comando do `orchestrator-rc`, e não pelo `.claude/settings.json` da pasta. Configuração da pasta vale para toda sessão aberta pela reserva. 
- O papel do orquestrador que vem de `--agent` também precisa ir para a pasta, porque o modo servidor não aceita a flag. Ponha `"agent": "<papel>"` no `.claude/settings.json` da pasta.  

bash, na máquina
```
cat > ~/.local/bin/orchestrator-spawn <<'EOF'
#!/bin/sh
# A entrada de reserva do orquestrador no app: o Remote Control no modo servidor, na pasta dele, abre
# uma sessão nova cada vez que você pede pelo app. A sessão lê o CLAUDE.md da pasta e já nasce
# orquestrador. Serve para quando a sessão principal cai e você está longe do SSH.
# Sem sessão pré-criada: ela gastaria memória do slice à toa enquanto o principal está de pé.
# O modo servidor sai depois de uns 10 minutos sem rede, e o laço o devolve.
. "$HOME/.config/always-on/env" || exit 1
export AGENT_ORCHESTRATOR AGENT_SLICE
cd "$HOME/$AGENT_ORCHESTRATOR" || exit 1
# Sem XDG_RUNTIME_DIR, o socket de mensagens cai em /tmp e a sessão não alcança os agentes.
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
export PATH="$HOME/.local/bin:$PATH"
while true; do
    claude remote-control --name "$AGENT_ORCHESTRATOR" --remote-control-session-name-prefix "$AGENT_ORCHESTRATOR" \
        --spawn same-dir --capacity 2 --no-create-session-in-dir --permission-mode bypassPermissions
    sleep 10
done
EOF
chmod 755 ~/.local/bin/orchestrator-spawn
```

O serviço tem o teto próprio de 1 GiB, dentro do slice dos agentes. Troque `voce`, `<uid>`, `<orquestrador>` e `<slice>` como no serviço do orquestrador: 

bash, na máquina
```
sudo tee /etc/systemd/system/<orquestrador>-spawn.service > /dev/null <<'EOF'
[Unit]
Description=Entrada de reserva do orquestrador no app: abre sessão nova já como orquestrador
After=network-online.target user-runtime-dir@<uid>.service
Wants=network-online.target user-runtime-dir@<uid>.service

[Service]
# A lista de pedidos: sem a primeira variável, os modelos novos não têm as ferramentas de tarefa.
Environment=CLAUDE_CODE_ENABLE_TODO_TOOLS=1
Environment=CLAUDE_CODE_TASK_LIST_ID=<orquestrador>
Type=forking
User=voce
Slice=<slice>.slice
MemoryHigh=768M
MemoryMax=1G
OOMPolicy=continue
ExecStart=/usr/bin/tmux -L <orquestrador>-spawn new-session -d -s <orquestrador>-spawn "bash -lic orchestrator-spawn"
ExecStop=/usr/bin/tmux -L <orquestrador>-spawn kill-server
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now <orquestrador>-spawn
```

Sessão da reserva em modo auto
Hoje o app troca o bypass por auto nas sessões abertas pelo modo servidor (issue #87826 (https://github.com/anthropics/claude-code/issues/87826)). O classificador do modo auto pode barrar o `agent start`, e a sessão da reserva pede aprovação. Quando o issue fechar, ela passa a rodar em bypass sem mudança no serviço. O orquestrador principal e os agentes sobem pelo terminal e mantêm o bypass. 
Confira com `tmux -L <orquestrador>-spawn capture-pane -p | tail -8`: a tela mostra `Ready` e `Capacity: 0/2`. No app, em sessão nova, o ambiente aparece como `<máquina>:<orquestrador>:<sufixo>`. O sufixo muda a cada reinício do serviço, e o ambiente antigo sai da lista. 

## A lista de pedidos 
O orquestrador recebe muitos pedidos, e o resumo da compactação, quando a conversa enche, pode perder um. A lista de tarefas nativa (https://code.claude.com/docs/en/interactive-mode#task-list) do Claude Code guarda cada pedido num arquivo, em `~/.claude/tasks/<orquestrador>/`, fora da conversa. Nos modelos novos ela vem desligada, e as duas variáveis dos serviços acima a ligam: a primeira traz as ferramentas `TaskCreate`, `TaskList` e `TaskUpdate`, e a segunda dá à lista o nome do orquestrador, a mesma no serviço principal e na entrada de reserva. 

- Pedido novo vira `TaskCreate` antes de qualquer ação, com o dono entre colchetes no assunto, como `[site] trocar o rodapé`. A regra está no `CLAUDE.md` do orquestrador. 
- O `agent start` liga as ferramentas no agente, que usa a lista da própria sessão. As subtarefas dele não enchem a sua. 
- O `agent stop <nome>` conclui as tarefas com `[<nome>]` no assunto. Para pausar um agente sem concluir, use `agent stop --keep-tasks <nome>`. 
- O mod `todo` do Cockpit (txt/mods.txt) põe a lista em cada prompt seu e arquiva a tarefa concluída.  
Logo depois da compactação, um hook da pasta põe na conversa as tarefas abertas e os agentes vivos: Ver o hook orchestrator-context 

bash, na máquina
```
cat > ~/.local/bin/orchestrator-context <<'EOF'
#!/usr/bin/env python3
"""Hook SessionStart do orquestrador: ao abrir, retomar e compactar, põe na conversa as tarefas abertas
da lista de pedidos e os agentes vivos. O resumo da compactação pode perder um pedido; a lista no disco,
não. O mod todo do Cockpit mostra a lista em cada prompt, mas numa conta Team ele não fica sabendo da
compactação, e este hook, do settings da pasta, roda nela.
"""
import json
import os
import re
import subprocess
from pathlib import Path

HOME = Path.home()
LIST = os.environ.get("CLAUDE_CODE_TASK_LIST_ID", "").strip()
parts = ["Estado do orquestrador, do hook SessionStart. Confira antes de responder."]

try:
    out = subprocess.run(["agent", "list"], capture_output=True, text=True, timeout=20).stdout.strip()
except (OSError, subprocess.SubprocessError) as e:
    out = f"(agent list falhou: {e})"
parts.append("## Agentes vivos\n" + (out or "nenhum"))

if LIST:
    rows = []
    for f in (HOME / ".claude" / "tasks" / re.sub(r"[^a-zA-Z0-9_-]", "-", LIST)).glob("*.json"):
        try:
            t = json.loads(f.read_text())
        except (OSError, ValueError):
            continue
        if t.get("status") in ("pending", "in_progress"):
            n = int(t["id"]) if str(t.get("id", "")).isdigit() else 0
            rows.append((n, f"- #{t.get('id')} [{t.get('status')}] {t.get('subject')}"))
    parts.append(f"## Tarefas abertas da lista {LIST} (TaskGet mostra cada uma inteira)\n"
                 + ("\n".join(r for _, r in sorted(rows)) or "nenhuma"))

print(json.dumps({"hookSpecificOutput": {"hookEventName": "SessionStart",
                                          "additionalContext": "\n\n".join(parts)}}))
EOF
chmod 755 ~/.local/bin/orchestrator-context
mkdir -p ~/<orquestrador>/.claude
cat > ~/<orquestrador>/.claude/settings.json <<EOF
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|compact",
        "hooks": [{ "type": "command", "command": "$HOME/.local/bin/orchestrator-context", "timeout": 30 }]
      }
    ]
  }
}
EOF
```

Confira pelo app: peça ao orquestrador "me lembra amanhã de renovar o domínio". A tarefa aparece em `ls ~/.claude/tasks/<orquestrador>/`, e depois de `/compact` ele ainda a cita. 

## Memória buscável (opcional) 
O ai-memory (https://github.com/akitaonrails/ai-memory), do Fábio Akita, dá aos agentes uma memória que se busca em linguagem natural, por MCP (https://modelcontextprotocol.io/), de qualquer pasta e de qualquer harness. Ele guarda as páginas em markdown no formato Open Knowledge Format (https://github.com/GoogleCloudPlatform/knowledge-catalog), com um índice SQLite ao lado. Com `AI_MEMORY=1` no `config.env`, o instalador (txt/instalador.txt) monta assim: 

- O serviço `ai-memory`, em `127.0.0.1:49374`, fora do slice dos agentes, com teto de 1 GiB. Ele ocupa uns 340 MB e fica sempre ligado. 
- Um espelho, a cada 10 minutos, da memória nativa do Claude Code: a pasta `memory` de cada projeto e a pasta global do mod `global-memory`. Os `.md` continuam a fonte, e o `MEMORY.md` continua entrando no início de cada sessão. 
- O MCP `ai-memory` em toda sessão. O agente busca com `memory_query`, e com `global=true` busca em todos os projetos.  

Sem os hooks de captura
O ai-memory também captura sozinho o que a sessão faz, por hooks. Num teste com senha falsa, a senha digitada num prompt foi gravada crua no banco, porque o filtro dele só reconhece formatos como `sk-` e `ghp_`. O instalador deixa esses hooks de fora e grava no servidor um padrão que apaga senha dita em frase, como "a senha do wifi é X". Senha vai para o cofre (txt/cofre.txt). 

## Falar com os agentes 

- O nome do agente no `agent start` é o nome dele no `ListAgents` e no app. O orquestrador manda continuação com `SendMessage` e pede `notify_when_idle` para saber quando ele termina. 
- Você também fala direto com o agente, pela sessão dele no app. 
- Arquivar a sessão no app não encerra o processo, e a RAM fica presa. Encerre com `agent stop`. 
- Agente encerrado volta na mesma conversa com `agent start <projeto> --name <nome> --resume <id>`. O `agent stop` grava o id em `~/.local/state/agents/stopped.jsonl`.  

## Provar 

bash, na máquina
```
agent start site --name teste "responda só: pronto"
agent list
agent result teste
agent stop teste
```

O `agent start` devolve o link da sessão e o grupo `/<slice>.slice/run-….scope`. O `agent list` mostra a RAM do agente contra o teto do projeto, o `agent result` responde `pronto`, e depois do `agent stop` o agente some do `agent list`. Pelo app, peça ao orquestrador a mesma tarefa e confira que ele abre, espera, relata e encerra sozinho. 
Com o orquestrador de pé, instale os mods do Cockpit (txt/mods.txt), o pacote de travas e indicadores para o Claude Code.
