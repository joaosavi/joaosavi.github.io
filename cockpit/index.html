Quickstart

Markdownllms.txt

Cockpit is a bundle of 12 mods for Claude Code. The guards stop an agent's mistake before it costs you: a secret in tool output, a pipe that hides a failed test, a build killed by the memory limit, a commit that sweeps in another session's edits. The instruments show where the session stands, under the prompt, under the spinner, and on a page with every session on the machine.

claude plugin marketplace add joaosavi/cockpit
claude plugin install cockpit@cockpit
  1. 1
    Install the bundle

    In a terminal, add the marketplace and install cockpit. It brings the 12 mods as dependencies.

    See every install step
  2. 2
    Restart and run the setup

    Restart Claude Code and type /cockpit:setup. It asks four questions with previews, writes the status line, the spinner tip and when to compact, and keeps a backup of the file it changed.

    See what the setup asks
  3. 3
    Work as usual

    The guards stay quiet until they act. Type /panel for the address of the session page, and /limit for the plan limits.

    What changes in your first session

Guards

Stop a mistake before it lands.

secret-guard

Replaces every secret value in tool output with <hidden:NAME> before the agent reads it, and writes the real value back when the agent edits a .env file.

collision-guard

Warns when another session on this machine edited the same file, and holds a git command once when it would take that session's uncommitted edits along.

pipefail

Adds set -o pipefail; to a test, typecheck or lint run piped into tail, head or grep, so a failed run cannot exit 0.

memory-guard /ram

Keeps typecheck, build, test and Playwright runs under the memory limit: as written, with one process, after a wait, or refused. Reruns a command killed with exit 137 with one process.

loop-breaker

Tells the agent to stop and change approach when it repeats the same error, the same fix or the same call.

usage-limit /limit

Limits each plan window on its own: one subagent at a time, a work-in-progress commit, a pause that keeps a reserve for you, and a resume when the window resets.

Instruments

Show where the session stands.

hud /hud

Model, project, git branch and PR, context window, plan limits and memory, in a status line under the prompt. Four styles.

spinner-status

Replaces the tip under the spinner with one line from Haiku: where the session stands, or a tip about these mods.

panel /panel

A local web page with a card for every session on this machine: its state, what it needs from you, the tool running now and the next step.

skill-loader

Delivers the right skill when the agent touches a matching file or writes a commit, and reminds it to diagnose before fixing when you paste an error.

Memory

global-memory

Adds a machine-wide memory folder beside the per-project memory, so facts about the machine reach every session.

todo

Shows the open tasks of the native task list at session start and on each prompt from you, and archives completed tasks.

Requirements

  • Claude Code 2.1.287 or later, on macOS, Windows or Linux. Mods use Claude Code's function hooks, which are in early access and may change between releases.
  • Node 22.18 or later, for the status line script.
  • Python 3.9 or later and curl, for the panel page. macOS and Windows 10 or later ship curl.
  • A Nerd Font in your terminal, for the status line icons. Without one, choose the plain icons during setup.

The status line, the spinner line and the panes are part of Claude Code's terminal interface. Run claude in a terminal: Terminal or iTerm on macOS, Windows Terminal or PowerShell on Windows, or the terminal panel of VS Code or JetBrains. The mods are not tested in the Desktop app or in the chat panel of the IDE extensions.

Install and set up

Markdownllms.txt

Two commands in a terminal, a restart, and a setup with four questions. It takes about five minutes.

Install

  1. Add the marketplace and install the bundle
    terminal
    claude plugin marketplace add joaosavi/cockpit
claude plugin install cockpit@cockpit

    The second command lists the mods it installs, as + 12 dependencies.

  2. Restart Claude Code

    The new session loads the mods. A session that was already open picks them up with /reload-plugins.

  3. Run the setup
    inside Claude Code
    /cockpit:setup

    A plugin cannot write the status line, the spinner tip or when to compact by itself, because they live in your settings.json. The setup writes them, keeps a backup of the file it changed, and tells you what you will notice.

What the setup asks

QuestionOptions
Status line stylerefined (recommended), blocks, minimal or compact, each with a preview drawn by the real script, with your own folder and branch.
IconsThe setup prints three Nerd Font icons and asks whether they show. If you see boxes, it uses plain arrows and marks that every terminal draws.
Time zoneOnly when the system is on UTC. It sets the clock times the mods show and what counts as today.
When to compactEarlier, at about 70% of a 1M model (recommended, 733000), Claude Code's default near the end, or at about half (500000). Skipped when the model's window is under 200K.

The setup also turns on auto-update for the marketplace, without asking. Run /cockpit:setup again to change an answer: it reads what is set and asks only about what you want to change.

Check the install

terminal
claude plugin list

You should see 13 entries ending in @cockpit, each marked enabled: the bundle and the 12 mods. An entry marked failed to load points to a version mismatch; see Troubleshooting.

Updates install by themselves

With auto-update on, a few minutes after the first message of a session, Claude Code updates every mod with a new version, installs any mod added to the bundle, and shows Plugin updated: <name> · Run /reload-plugins to apply. To turn it off, open /plugin, go to Marketplaces, and select cockpit.

macOS, Windows and Linux

Every mod runs on all three systems, and they are tested on Linux only. Two things differ:

  • memory-guard and the memory figure of the hud read cgroup limits and /proc/meminfo on Linux. On macOS they read vm_stat and on Windows PowerShell, and there they compare against the whole machine's memory. The macOS and Windows readings are tested only against simulated output.
  • The panel page shows memory by cgroup, systemd services and the share of CPU time spent waiting on disk only on Linux.

On Windows, the setup points the status line at Node instead of the .sh script, because PowerShell cannot run a shell script.

On a Team or Enterprise plan

Every mod works the same on every plan, except global-memory. Team and Enterprise plans run a built-in guard that skips plugins you install yourself on the two hooks it needs, so it installs and does nothing until your organization lists it in managed settings. The other mods run as usual. The global-memory page shows the two settings.

Coming from the agent marketplace

Cockpit was called agent before October 2026. Rename every @agent key to @cockpit in ~/.claude/settings.json, then run claude plugin marketplace remove agent before the steps above. Removing a marketplace deletes the saved options of its plugins, so rename the keys first, or run /cockpit:setup again afterwards.

Guards

secret-guard

Markdownllms.txt
v1.3.0

Hides every secret value in tool output before the agent reads it.

Why

A secret that reaches the transcript is sent to the model and kept in the session log, and from then on it must be rotated. Tool output leaks secrets easily: env, cat .env, a stack trace with a connection string. This mod replaces each value with <hidden:NAME> in every tool result, built-in, MCP and subagent alike.

What it does

  • The values come from the secrets file and every file in the folder beside it named like it plus .d (~/.secrets.d/ by default), from every .env* file under the .env root (5 levels deep) when you set one, from environment variables with a secret-looking name (TOKEN, SECRET, PASSWORD, KEY, AUTH and others), and from the password of every scheme://user:password@ URL.
  • Known token formats are hidden even when no list has them: GitHub, Anthropic, OpenAI, AWS, Google, Stripe, Slack, JWT and private key blocks. They show as <hidden:github>, <hidden:jwt> and so on.
  • A tool that hands out secrets, such as a password vault CLI, can keep its own NAME="value" list in a file in the secrets folder, without touching your secrets file. A file whose name starts with a dot is skipped, so the tool can write a temporary file and rename it into place.
  • A value that also appears in a .example file is already public and stays visible.
  • When the agent writes <hidden:NAME> into a .env file or the secrets file, the mod writes the real value in its place. The agent edits those files without ever seeing a value.
  • When the agent writes <hidden:NAME> in a Bash command, the mod runs the command with the real value, and the output comes back hidden as usual. The transcript keeps the command as written. The agent can call an API with a token it never sees.
  • A placeholder the mod cannot fill stops the command instead: a token known only by its format, or a name with two different values in your files, such as the same DATABASE_URL in two projects. The agent is told to read the value inside the command, from its variable or .env file.
  • If the mod itself fails, it withholds the output instead of passing it unchecked.

Options

OptionDefaultWhat it does
enabledtrueOff, the mod does nothing: every value shows in tool output as it is. Takes effect in the next session, or after /reload-plugins.
secretsFile~/.secretsKEY=value file whose every value is a secret, whatever its name.
envRootemptyFolder searched for .env files, 5 levels deep. Empty searches none.
minLength12Shorter values are left alone, except known token formats and the values of the secrets files.
fillCommandstrueRun a Bash command that names <hidden:NAME> with the real value. Off, such a command does not run, and the agent is told to read the value inside the command.

By default the mod reads no .env files. To cover your projects' .env files too, set envRoot to the folder that holds your repos, such as ~/code. The mod then scans it at start, checks its folders for new .env files at most once a minute, and rebuilds the list at least every 10 minutes.

What it records

~/.local/state/mods/secret-guard/<day>-<session>.jsonl: one line each time the list is rebuilt (with how long it took), a result is redacted, a placeholder is restored or filled in a command, or a command is stopped, with secret names and counts only, plus one session-summary line. The values live only in the mod's memory, never on disk. Each line has at, session and event.

Cost

The hook added about 64 ms per tool call on the author's Linux machine (60 calls measured in October 2026, an estimate), with envRoot set to a folder of about 140 subfolders, most of it checking whether a source file changed.

Limits

  • A secret shorter than minLength that matches no known format stays visible. A value from the secrets file or its folder is hidden from 6 characters, because a vault hands out passwords of 8 to 11; under 6, a value is a PIN or a word, and hiding it would garble ordinary output.
  • A secret that the agent already saw before this mod loaded is still in the transcript.
  • A .env file outside envRoot is not read, so its values stay visible unless another source has them.
  • Filling a placeholder in a command lets the agent use a secret, including sending it to a server. It cannot do more than it already could with source .env, but the command runs without a prompt of its own.
  • Placeholders are filled back in Bash commands only. On Windows without Git Bash, a PowerShell command with a placeholder runs as written. Output of every tool is still hidden.
  • Tested on Linux only. The macOS and Windows paths are covered by unit tests with a simulated environment.

collision-guard

Markdownllms.txt
v1.3.0

Warns when two Claude Code sessions on the same machine work on the same files, and holds a git command once when it would take another session's uncommitted edits along.

Why

Running several sessions at once is common, and two of them often land in the same repo. On the author's Linux machine, 11 pairs of sessions edited the same repo less than 30 minutes apart in 8 days, and 5 of those pairs edited the same file. Claude Code's Edit already refuses a file changed since it was read, so one session does not silently overwrite the other. What it does not catch is git: git add -A or git commit -a in one session stages the other session's half-done edits, and git stash, checkout or reset --hard moves or discards them.

What it does

  • Each session keeps one record in ~/.local/state/mods/collision-guard/sessions/<session>.json with the files it edited. Only that session writes it.
  • After an edit, when another live session also edited that file and git still shows its change, the agent reads a note naming the session and how long ago, and you see a toast. Outside any git repo, the other edit counts for windowMinutes. Each edit of the other session warns once.
  • Before a git command that would stage, commit, stash, switch away from or discard another session's uncommitted edits, the mod holds it and lists those files. The agent can name its own files instead, or run the same command again within 2 minutes to let it through.
  • It reads cd earlier in the line and git -C <dir> to find the repo. Quoted text, such as a commit message, is not read as a command.
  • A command that names paths, such as git add -A mods/ or git checkout -- src/a.ts, is held only for the other session's edits under those paths. A wildcard or :/ counts as the whole repo.
  • Ended sessions mark their record, and records older than expireHours are removed when a session starts.

Options

OptionDefaultWhat it does
enabledtrueOff, the mod does nothing: no record, no warning, no git hold. Takes effect in the next session, or after /reload-plugins.
gitconfirmconfirm holds a risky git command once. note lets it run and tells the agent afterwards. off leaves git commands alone.
windowMinutes30How long another session's edit to a file outside any git repo still counts. Inside a repo, an edit counts while git shows the file as changed.
expireHours24A session silent this long counts as gone, and its record is removed.
editWarningstrueTell the agent, and show a toast, when another session edited the same file. Off, edits are still recorded, so the other sessions and the git guard still see them.

What it records

~/.local/state/mods/collision-guard/<day>-<session>.jsonl: one line per warning (edit-warned, git-held, git-confirmed, git-noted) with the git operation and how many files, never a file's content, plus one session-summary line. Each line has at, session and event.

Cost

A tool call that is neither an edit nor a git command costs nothing measurable. An edit reads the other sessions' records and runs git rev-parse once per folder; when another session edited the same file, it also runs git status on it. In the first live test, the edit that found a collision took 444 ms of hook time, and the others under 60 ms (7 calls, October 2026).

Limits

  • Sessions must share the machine and the home folder. Sessions on another computer, or in a container with its own home, are not seen.
  • A file changed by a Bash command (sed -i, a script, a formatter) is not recorded as an edit. Only Edit, Write, MultiEdit and NotebookEdit are.
  • git checkout <name> reads the same whether <name> is a branch or a file, so the note says "to another branch or an older version".
  • Tested on Linux only. On Windows, paths are compared with forward slashes, as git prints them, and git commands through the PowerShell tool are checked like Bash ones. A cd to a Git Bash path such as /c/work is not followed.

Guards

pipefail

Markdownllms.txt
v1.3.0

Adds set -o pipefail; to a command that pipes a test, typecheck or lint run into tail, head or grep.

Why

A pipeline exits with the code of its last command. yarn test | tail -20 exits 0 when tests fail, because tail succeeded, and the agent reads a pass. Rewriting the command costs nothing and saves the agent a wrong conclusion.

What it does

  • Matches a runner where it runs: yarn, npm run, pnpm or bun run with test, e2e, typecheck, lint, check and similar scripts, or with a script named in extraRunners, plus turbo run, vitest, jest, playwright test, tsc, vue-tsc, eslint, pytest, go test and cargo test. Quoted text and heredoc bodies do not count.
  • Puts set -o pipefail; in front, runs the command, and tells the agent that a | head can make a runner exit 141 (SIGPIPE).
  • Leaves alone a command that already mentions pipefail.
what the mod rewrites
yarn test | tail -20
# becomes
set -o pipefail; yarn test | tail -20

Options

OptionDefaultWhat it does
enabledtrueOff, the mod does nothing: no command is rewritten. Takes effect in the next session, or after /reload-plugins.
extraRunnersempty listScript names that also count as runners when a package manager calls them: yarn <name>, npm run <name>, pnpm <name>, bun run <name>.

Add a repo's own check script here when its exit code says whether the code works, such as verify for a script that runs lint, types and tests. The mod then rewrites yarn verify | tail too.

What it records

~/.local/state/mods/pipefail/<day>-<session>.jsonl: one line per rewrite naming the runner (yarn vitest, never the whole command), plus one session-summary line. Each line has at, session and event.

Cost

The hook added about 2 ms per Bash call on the author's Linux machine (56 calls measured in October 2026, an estimate).

Limits

  • Only tail, head and grep as the filter. Other filters, such as sed or awk, are left alone.
  • A runner hidden inside a script the command calls is not seen.
  • Only the Bash tool. On Windows without Git Bash, commands run through the PowerShell tool and the mod leaves them alone. Tested on Linux only.

memory-guard

Markdownllms.txt
v1.3.0/ram

Keeps typecheck, build, test and Playwright runs under the memory limit, and reruns a command killed with exit 137 with one process. On Linux the limit is the tightest cgroup limit or the machine's memory; on macOS and Windows it is the machine's memory.

Why

On Linux, when memory runs out, or a cgroup reaches its memory.max, the kernel kills the largest process, which is usually the heavy command, and the agent sees exit 137 without knowing why. This mod checks the headroom before a heavy command runs and adapts the command to it.

What it does

Before a heavy command runs, the mod compares its expected peak with the headroom, minus the margin. The headroom is the machine's available memory, or the room left under the tightest cgroup limit when the session runs in one, as under a systemd service or in a container:

  1. It fits

    It runs as written.

  2. Only a single process fits

    The mod adds --concurrency=1, --workers=1 or --maxWorkers=1 and tells the agent.

  3. Nothing fits

    The mod waits up to waitSeconds for memory to free up.

  4. Memory does not free up

    The mod refuses the command and tells the agent what uses the memory.

After the command, the mod stores its measured peak for the next estimate, and reruns with a single process a command that died with exit 137. Until a command is measured, the estimates are 1 GB for typecheck and build, 600 MB for tests and 500 MB for Playwright.

Without a cgroup limit, as on most Linux desktops and laptops, the headroom is MemAvailable from /proc/meminfo. On macOS it is the free, inactive, speculative and purgeable pages of vm_stat, against the total of sysctl -n hw.memsize. On Windows it is FreePhysicalMemory against TotalVisibleMemorySize, read through PowerShell. Under a cgroup limit, it counts the working set: memory.current minus inactive_file, which the kernel frees before it kills anything.

Commands

/ram shows the headroom, each cgroup's use and limits when there are any, and the measured peaks. It says there is no memory reading when the system gives none. In a terminal it also opens the Memory pane: a bar per cgroup with the high mark, refreshed every 2 seconds. Press r to refresh and esc to close.

Options

OptionDefaultWhat it does
enabledtrueOff, the mod does nothing: heavy commands run as written, and /ram is gone. Takes effect in the next session, or after /reload-plugins.
margin2Share of memory kept free: of each cgroup's memory.max, or of the machine's total without a cgroup limit. The high mark counts only for a cgroup with no max.
waitSeconds120How long a heavy command waits for memory before it is refused.
reducetrueWhen only a single process fits, add --concurrency=1, --workers=1 or --maxWorkers=1.
waittrueWhen nothing fits, wait up to waitSeconds. Off, the next step comes at once.
refusetrueWhen memory does not free up, refuse the command. Off, it runs as written and may be killed.
retry137trueRerun with a single process a command killed with exit 137.

What it records

  • ~/.local/state/mods/memory-guard/<day>-<session>.jsonl: one line per reduced, refused or retried command and per measured peak, plus one session-summary line with the time commands waited.
  • The last 3 measured peaks of each command, in the shared mod store under peaks.

Cost

The hook added about 4 ms per Bash call on the author's Linux machine, not counting the time commands waited for memory (56 calls measured in October 2026, an estimate). Each heavy command also reads the memory files once a second while it runs, to measure its peak. On macOS and Windows a reading runs a command instead, and stays fresh for 10 seconds: sysctl and vm_stat take a few milliseconds, and PowerShell about a second to start (an estimate).

Limits

  • The peak is measured on the whole cgroup, or the whole machine without one, so another session starting at the same time inflates it. Keeping only the last 3 measurements lets an inflated one age out.
  • tsc has no flag for a single process, so a typecheck that does not fit waits or is refused.
  • A background command returns at once and gives no measurement.
  • The macOS and Windows readings are tested only against simulated vm_stat, sysctl and PowerShell output. There the headroom is the whole machine's, with no per-session limit, and a reading can be up to 10 seconds old.
  • When the reading fails, heavy commands run as they came, nothing waits or is refused, and no peak is stored. /ram says there is no reading. The rerun with one process after an exit 137 still applies.

loop-breaker

Markdownllms.txt
v1.3.0

Notices when the agent goes in circles and tells it to stop and change approach.

Why

An agent that keeps editing the same file after the same failure burns tokens and time without getting closer. A short nudge at the right moment makes it step back, which a rule in CLAUDE.md does not do reliably.

What it does

The mod counts three signals per agent loop (the main conversation and each subagent), reset at the end of each turn:

  • Fix attempts: edits to one file while a command that failed has not passed again.
  • Repeated errors: the same error coming back, with numbers, paths and quoted values ignored.
  • Repeated calls: the same tool with the same arguments, in a row.

When a count reaches its limit, the mod adds a note to the tool result. The note starts with Loop check and asks the agent to write what it tried, then re-read the code, form a new hypothesis, or ask you. Nothing is refused.

Options

OptionDefaultWhat it does
enabledtrueOff, the mod does nothing: no count, no nudge. Takes effect in the next session, or after /reload-plugins.
editLimit5Fix attempts on one file in one turn before the nudge.
errorLimit3Times the same error may come back in one turn before the nudge.
repeatLimit3Identical tool calls in a row before the nudge.
editChecktrueNudge after editLimit fix attempts on one file.
errorChecktrueNudge after the same error comes back errorLimit times.
repeatChecktrueNudge after repeatLimit identical calls in a row.

What it records

~/.local/state/mods/loop-breaker/<day>-<session>.jsonl: one line per nudge with its kind and count, plus one session-summary line. Each line has at, session and event.

Cost

The hook added about 2 ms per tool call on the author's Linux machine (60 calls measured in October 2026, an estimate).

Limits

  • A failure is read from the exit code and from failure words in the output, so a tool that fails silently is not counted.
  • Counts reset at the end of each turn, so a loop that spans several turns is not caught.
  • Tested on Linux only.

Guards

usage-limit

Markdownllms.txt
v1.3.0/limit

Keeps the account usage limit from running out in the middle of a task.

Why

When a 5-hour or 7-day window reaches 100%, the session stops wherever it is, often mid-edit, and nothing resumes it. This mod slows down before that point, has the agent commit its work, stops at a reserve you keep for yourself, and resumes the session on its own when the window resets.

The three stages

Each window has three stages, each with its own switch and percentage:

Stage5-hour window7-day window
Throttle: one subagent at a time90%97%
Commit: ask for a wip: commit97%98%
Pause: keep the rest for you98%99%

The 7-day limits also apply to the per-model weekly windows, such as seven_day_opus. Each window is judged by its own limits, and the most restrictive result applies: a paused window beats a throttled one. When two windows are paused, the one that resets last holds the session.

What it does

  • From the throttle, only one subagent runs at a time.
  • From the commit stage, the agent is asked once per window to commit its work in progress in each repository it changed, with a wip: message and without pushing. It stages only the files it changed, so the work of another session in the same repository stays out. Only the main conversation gets the request.
  • At the pause, every tool call is refused except a command that only stages and commits (git add, git commit, cd, chained with &&), so the work still gets committed when a burst of requests jumps straight past the commit stage. The agent writes in up to 3 lines where it stopped, and the mod schedules the resume for the reset time plus 2 minutes.
  • A prompt you type during the pause gets one turn without subagents, spent from the reserve.
  • A prompt nobody typed (a routine, another session, a task notification) is held and delivered with the resume.
  • The band above the prompt shows each window with a bar, its own pause mark, the percent and the reset time, from 75% by default. Each bar turns yellow from its window's throttle or commit stage and red from its pause.
  • The status line under the prompt shows the state while the mod holds something back.

The server builds a digest of the transcript, at most 48,000 characters long: the message that opened the task, then the newest rows that fit, each tool call cut to one line. Each summary is one claude -p call, and it counts toward your plan's usage limits. At API list prices with sonnet, a summary cost about $0.07, and with four sessions working the page spent up to $2.40 an hour. todo

Markdownllms.txt
v1.5.0

Keeps Claude Code's native task list in front of the agent: the open tasks at session start and on each prompt from you, a reminder that a new request becomes a task first, and completed tasks moved to an archive log.

Why

The task tools (TaskCreate, TaskList, TaskUpdate, TaskGet) write one JSON file per task in ~/.claude/tasks/<list>/, so the list outlives a compaction, --resume and --continue. The model forgets that the list is there. After a compaction it works from the summary, and a request that lived only in the conversation is lost. A session that takes many requests, such as a manager that hands work to other agents, needs the list read back to it from disk.

What it does

  • At session start, adds a note with the open tasks of the session's list.
  • On each prompt from you, attaches the open tasks and the tasks completed since the last prompt. Messages from other sessions, notifications and schedules get nothing.
  • With a named list (CLAUDE_CODE_TASK_LIST_ID), the same prompt also carries the rule: a new request becomes a TaskCreate before any other work, with its owner in the subject, such as [owner] what was asked.
  • Moves a completed task to ~/.local/state/mods/todo/<list>.jsonl and deletes its file, so the list holds only open work. This covers a task completed by TaskUpdate and a task file a script rewrote.

Order of the list

The open tasks go in one group per state, with a count, such as waiting (2):.

  • A task's priority and state come from metadata.priority and metadata.state in its file. Without metadata, they come from a subject such as [owner] P1 waiting: what was asked: the P number after the owner, then the word before the colon.
  • A task with no state goes in the group of its native status, in_progress or pending.
  • In each group, tasks go from P0 up, then the ones with no priority, then by id.
  • The group that holds the most urgent task comes first. On a tie, the group with a task in progress comes first.

Turn on the task tools

Claude Code offers the task tools by default only on Opus 4.7, Sonnet 4.6, Haiku 4.5 and earlier models. On a newer model, start Claude Code with the variable set. To share one list between sessions, name the list too:

terminal
CLAUDE_CODE_ENABLE_TODO_TOOLS=1 CLAUDE_CODE_TASK_LIST_ID=requests claude

Options

OptionDefaultWhat it does
enabledtrueOff, the mod does nothing. Takes effect in the next session, or after /reload-plugins.
remindtrueWith a named list, each prompt from you carries the request rule.
archivetrueMoves completed tasks from the list to the archive log. Off, completed tasks stay in the list.

What it records

~/.local/state/mods/todo/<day>-<session>.jsonl: one line per note, prompt context and archive run, plus one session-summary line. The archive, one line per completed task, is ~/.local/state/mods/todo/<list>.jsonl. Each line has at, session and event.

Cost

The open tasks go in whole with each prompt from you, at about 15 tokens per task, 30 tasks at most. The only tool.call hook is on TaskUpdate.

Limits

  • On a Team or Enterprise plan, the built-in guard sec-default@builtin skips the session.compact hook of a mod you installed yourself, so the note right after a compaction does not appear. The next prompt from you carries the list. A SessionStart hook with the matcher compact in the session's settings.json can print the open tasks right away.
  • Task ids restart at 1 after every file has left the list. The archive keeps the subject next to each id.
  • Tested on Linux only.

Install this mod alone

The cockpit bundle already installs todo with the other mods. To install it alone:

terminal
claude plugin marketplace add joaosavi/cockpit
claude plugin install todo@cockpit

Configure and turn mods off

Markdownllms.txt

Every mod option is a row in /config. The setup handles the few settings a plugin cannot write itself.

Change an option

Open /config and scroll to the mod. Each mod's page lists its options, their defaults and what they do. The status line picks up a change within five seconds; for the other mods, restart Claude Code or run /reload-plugins.

In the settings file

The same options live under pluginConfigs in ~/.claude/settings.json, keyed by <mod>@cockpit. This is useful to share a setup across machines:

~/.claude/settings.json
{
  "pluginConfigs": {
    "hud@cockpit": { "options": { "style": "blocks", "icons": "unicode" } },
    "usage-limit@cockpit": { "options": { "timeZone": "Europe/Lisbon" } },
    "collision-guard@cockpit": { "options": { "git": "note" } }
  }
}

Every mod has an Enabled option. Turn it off in /config, or set "enabled": false under the mod's pluginConfigs entry, then start a new session or run /reload-plugins. Off, the mod registers no hook and costs nothing per tool call. /cockpit:setup can also turn mods off for you.

Run on a remote machine

Markdownllms.txt

If you run Claude Code on a remote Linux machine over SSH, the mods work the same, and a few parts do more.

Open the page through a tunnel

panel listens only on 127.0.0.1 of the machine where the sessions run. From your computer, open an SSH tunnel, then open http://localhost:7777. In a session opened over SSH, /panel prints this command with the machine's name.

on your computer
ssh -N -L 7777:127.0.0.1:7777 <host>

To open the tunnel with every SSH login, add one line to the host's entry in ~/.ssh/config on your computer:

~/.ssh/config
Host <host>
  LocalForward 7777 127.0.0.1:7777

Run the page as a service

Instead of letting a session start the page, run it under systemd. Set the panel option autostart to false, then run the server as a unit:

systemd unit
[Service]
User=<user>
ExecStart=/usr/bin/python3 -I /home/<user>/.claude/plugins/marketplaces/cockpit/panel/server/panel.py
Environment=PANEL_CLAUDE=/home/<user>/.local/bin/claude
Restart=always

PANEL_PORT, PANEL_MODEL and PANEL_REFRESH_MINUTES set the server's options. Set PANEL_GROUPS to a comma-separated list of cgroup paths, such as agents.slice, to show those groups and everything under them on the page.

Memory limits

When sessions run under a cgroup v2 memory limit, as a systemd service or a container sets, memory-guard keeps heavy commands under the tightest limit, the hud shows the room left under it, /ram shows each group, and the page shows each group's memory and the state of its systemd services.

Remote Control and tmux

Every Cockpit command also answers in plain text, so it works when you drive a session over Remote Control from claude.ai or the mobile app, where no pane is drawn. The page links a session to claude.ai when the session runs with Remote Control. For a session that runs in tmux, its tmux button copies the command that attaches to its pane.

What leaves your machine

Markdownllms.txt

Cockpit runs inside Claude Code on your machine. Two mods send an excerpt of the session to a model, through your own account. Everything else stays local.

What leaves

ModSendsWhen
panelAn excerpt of each session's transcript, through claude -p, to sonnet by defaultOn Refresh, when a session goes idle after a turn, and every 5 minutes for a session that changed
spinner-statusThe last few prompts and the agent's last text, at most 3,000 characters, to HaikuOnce per turn, or never in tips mode
hudA gh pr view request for the current branch, to GitHubAt most once a minute, when gh is installed

These calls use the same account and the same data terms as the rest of your Claude Code session. No other mod calls a model.

What stays

  • Every mod writes a diary under ~/.local/state/mods/<mod>/, one line per action and one summary per session. A diary never holds a secret value or a file's content.
  • collision-guard keeps the list of files each session edited. An ended session marks its record, and records older than expireHours (24 hours by default) are removed when a session starts.
  • secret-guard holds secret values in memory only, never on disk.
  • panel keeps the last summary of each session. The page has no login and listens only on 127.0.0.1. Anyone who can reach that port can read it and type into your sessions, so do not expose it.

Troubleshooting

Markdownllms.txt

The problems people hit most, and the fix for each.

SymptomFix
The status line does not show, or only changes when a message arrivesThe statusLine setting is missing, or has no refreshInterval. Run /cockpit:setup again, then restart Claude Code.
The status line shows nothing at allThe script needs Node 22.18 or later. Run node --version, and update Node if it is older.
Icons show as boxes or question marksThe terminal font has no Nerd Font glyphs. Set icons to unicode under hud in /config, or install a Nerd Font and select it in your terminal.
The bars look like a single blurred shapeSome fonts draw the bar glyphs joined together. Set bar under hud to dots or squares.
Two lines show under the spinnerClaude Code's own tip is still on. Set "spinnerTipsEnabled": false in your settings, or run the setup again.
A mod shows failed to load in claude plugin listThe marketplace copy and the installed version are out of step. Run claude plugin marketplace update cockpit, then claude plugin update cockpit@cockpit, and restart.
The mod options are goneRemoving a marketplace deletes the saved options of its plugins. Run /cockpit:setup again to write them back.
global-memory does nothing on a Team or Enterprise planThose plans skip user-installed plugins on the hooks it needs. It must run as an organization plugin; its page shows the managed settings.
/panel says the page server is not runningThe server starts when a session starts, unless autostart is off. Check that Python 3.9 or later is installed as python3, python or py, and that curl runs, then start a new session. The server writes its errors to ~/.local/state/mods/panel/server.log.
The page greys out the options of a sessionThe session has not checked its inbox in the last 15 seconds, usually because it loaded an older panel mod. Run /reload-plugins in that session.
The Mods drawer shows no memory groups or servicesThat is expected on macOS and Windows. The page shows memory by group only for Linux cgroup v2 groups with a limit, and services only under systemd.
/ram says there is no memory readingmemory-guard found no /proc/meminfo, and the system command failed: sysctl and vm_stat on macOS, or PowerShell on Windows, missing or slower than its timeout. Until a reading works, heavy commands run as written.
A git command was refused with a list of filescollision-guard held it, because another session on this machine has uncommitted edits in the same repo, under the paths the command names. Name your own files instead, or run the same command again within 2 minutes.

Update and uninstall

Markdownllms.txt

Updates arrive by themselves, a few minutes after the first message of a session. You can also update by hand, and remove everything in two commands.

Automatic updates

The setup turns on auto-update for the cockpit marketplace. Claude Code then refreshes the marketplace once per session and updates every Cockpit mod with a new version, each one on its own. The open session keeps the versions it loaded until you run /reload-plugins; the next session loads the new ones.

Update by hand

Updating the bundle does not update the mods: each mod is its own plugin. To update them all now:

terminal
claude plugin marketplace update cockpit
for m in $(claude plugin list | grep -o '[a-z-]*@cockpit'); do claude plugin update "$m"; done

To update one mod, name it: claude plugin update hud@cockpit.

A mod that is new in a release does not arrive with the update: the bundle then lists it as a missing dependency. Install it by name, such as claude plugin install todo@cockpit for 1.4.0.

Uninstall

terminal
claude plugin uninstall cockpit@cockpit
claude plugin prune

Uninstalling the bundle leaves the mods installed; claude plugin prune removes them. The setup wrote statusLine, spinnerTipsEnabled and autoCompactWindow to your settings file and kept a backup next to it. Remove those keys by hand, or restore the backup.

Remove the data

The mods leave their diaries in ~/.local/state/mods/. Delete that folder to remove everything Cockpit wrote.
